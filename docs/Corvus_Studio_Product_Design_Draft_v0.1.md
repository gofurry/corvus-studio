# Corvus Studio 产品设计草案 v0.1

> 状态：Draft\
> 项目：Corvus Studio\
> 首发方向：Launch Workspace\
> 未来方向：Watch Workspace

------------------------------------------------------------------------

## 1. 产品愿景

Corvus Studio 是一个面向独立游戏团队的本地优先开源工作台。

它帮助开发者：

-   组织 Steam 发售准备工作；
-   管理发布所需资产；
-   跟踪发布目标和准备状态；
-   使用 AI Agent 发现风险和缺失；
-   在保持数据控制的前提下辅助运营决策。

核心理念：

> Launch inward. Watch outward.

向内推进自己的游戏发售，向外观察市场变化。

------------------------------------------------------------------------

# 2. 产品结构

## Corvus Studio

总项目和应用。

包含：

-   Launch Workspace
-   Watch Workspace（未来）
-   Project Codex
-   Agent 能力层

## Launch Workspace

首个实现方向。

负责：

-   Steam 发布准备；
-   发售清单；
-   商店资产；
-   项目知识；
-   AI 发售诊断。

## Watch Workspace

未来实现。

负责：

-   Steam 公开市场数据；
-   竞品观察；
-   市场趋势分析。

首版仅保留入口。

------------------------------------------------------------------------

# 3. 产品定位

Corvus Studio 不是：

-   通用项目管理软件；
-   游戏引擎工具；
-   通用文件管理器；
-   通用 AI 聊天工具。

它是：

> 独立游戏发售运营工作台。

核心问题：

"我的游戏距离公开发布还缺少什么？"

------------------------------------------------------------------------

# 4. Launch 核心模型

## Game Project

一个游戏对应一个项目。

保存：

-   游戏定位；
-   核心卖点；
-   目标玩家；
-   发售计划；
-   项目资料；
-   宣传资源；
-   运营决策。

------------------------------------------------------------------------

## Project Codex

项目知识档案。

用于让 Agent 理解项目。

包含：

-   游戏介绍；
-   核心玩法；
-   美术风格；
-   目标用户；
-   对标作品；
-   品牌语气；
-   禁止表达；
-   已确认事实；
-   待决定事项。

------------------------------------------------------------------------

## Release Goal

发布目标。

例如：

-   Steam Coming Soon 页面；
-   Demo 发布；
-   抢先体验；
-   正式发售；
-   大版本更新。

不同目标生成不同准备流程。

------------------------------------------------------------------------

# 5. 清单系统

清单是主要工作流。

内置：

-   Steam 规则模板；
-   Corvus 行业经验模板。

模板具有：

-   来源；
-   版本；
-   更新时间；
-   适用范围。

项目中的清单属于用户，可自由修改。

任务来源：

-   Steam requirement
-   Corvus template
-   User task
-   Agent suggestion

------------------------------------------------------------------------

# 6. 资源系统

资源不是简单文件，而是 Resource。

支持：

-   本地文件；
-   本地目录；
-   URL；
-   云端资源链接；
-   文档；
-   视频；
-   图片；
-   文本资料。

------------------------------------------------------------------------

## Creative Library

自定义素材库。

保存：

-   原始图片；
-   PSD；
-   Logo；
-   视频；
-   Trailer；
-   宣传资料；
-   社交媒体素材。

------------------------------------------------------------------------

## Steam Deliverables

Steam 发布交付目录。

保存：

-   Capsule；
-   Screenshot；
-   Trailer；
-   Store Copy；
-   Localization。

特点：

-   可检查；
-   可上传；
-   有版本；
-   关联源素材。

------------------------------------------------------------------------

# 7. Asset Map

资产地图不是通用白板。

用于展示：

-   源素材；
-   Steam 交付物；
-   发布节点；
-   卖点；
-   宣传内容。

例如：

源主视觉

→ Main Capsule

→ Steam 商店页

→ 发售节点

------------------------------------------------------------------------

# 8. AI Agent 设计

## DeepSeek

主 Agent。

负责：

-   项目分析；
-   工具调用；
-   文案生成；
-   清单诊断；
-   最终报告。

------------------------------------------------------------------------

## Seed 多模态模型

负责：

-   图片检查；
-   视频检查；
-   音频检查；
-   视觉风险分析。

------------------------------------------------------------------------

## Kimi K3

用于：

-   长视频理解；
-   长上下文分析；
-   复杂多模态任务。

------------------------------------------------------------------------

## Gemini

用于：

-   通用多模态；
-   替代模型；
-   高级分析。

------------------------------------------------------------------------

# 9. 模型架构原则

不做通用模型聚合平台。

采用：

> 模块化能力层 + 少量官方模型适配。

内部根据能力选择：

-   文本推理；
-   图片分析；
-   视频分析；
-   音频分析；
-   长上下文。

外部只提供经过验证的模型。

------------------------------------------------------------------------

# 10. Agent 检查原则

检查分三类：

## 确定性检查

程序完成：

-   文件存在；
-   尺寸；
-   格式；
-   缺失项。

## 多模态检查

模型完成：

-   视觉表现；
-   内容覆盖；
-   素材一致性。

## Agent 诊断

综合：

-   项目状态；
-   清单；
-   资产；
-   模型结果。

输出：

-   Blockers；
-   Warnings；
-   Advice；
-   Next Actions。

------------------------------------------------------------------------

# 11. 首页与工作流

首页：

> 发布目标

不是聊天入口。

主要流程：

1.  创建项目；
2.  选择 Release Goal；
3.  生成清单；
4.  准备资源；
5.  检查交付物；
6.  Agent 诊断；
7.  完成发布准备。

------------------------------------------------------------------------

# 12. v0.1 范围

-   通用白板。

------------------------------------------------------------------------

# 13. 本地优先原则

默认：

-   数据存储本机；
-   单用户模式；
-   本地运行。

云模型调用：

-   明确告知发送内容；
-   用户可控制；
-   支持替换模型；
-   不默认上传全部资源。

------------------------------------------------------------------------

# 总结

Corvus Studio 的核心不是 AI 聊天，而是：

> 将独立游戏发布过程转化为可管理的目标、清单、资源、证据和 AI
> 辅助诊断系统。
